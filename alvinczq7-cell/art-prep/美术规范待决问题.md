## 🔴 第一批：最先要问组长的（不定下来没法开工）

### Q1 · 游戏内部分辨率（画面「原生」多大）　✅ 已解决（2026-11-26）

**已定 960×540**，整张 ×2 放大到 1080p。理由与换算表见 [ADR 0002](../../decisions/0002-基准分辨率与三层尺寸.md)。下面原来的三个选项（320×180 / 480×270 / 640×360）均未采用，仅留档：

| 选项 | 放大倍数到 1080p | 特点 |
|---|---|---|
| 320×180 | 6 倍 | 很复古，格子大，细节少，画得快 |
| 480×270 | 4 倍 | 折中，很多现代像素游戏用 |
| 640×360 | 3 倍 | 细节多，hi-bit 感强，但每张图工作量大 |

> 遗留：引擎还没定（docs/30-tech 是空的）。1440p 屏对 960×540 非整数倍，ADR 里写了低优先级。

### Q2 · 等距砖块尺寸　✅ 已解决（2026-11-26）

**已定 tile = 32px（菱形 32×16）**，见 [ADR 0002](../../decisions/0002-基准分辨率与三层尺寸.md)。原选项留档：

| 选项 | 菱形 | 取舍 |
|---|---|---|
| 32px | 32 宽 × 16 高 | 工作量小，配 320×180 / 480×270 合适；小人只能很小 |
| 48px | 48 × 24 | 中间值 |
| 64px | 64 × 32 | 细节足，配 640×360；建筑、家具工作量翻倍 |

> 注：原表里「32px 配 320/480，小人只能很小」的判断前提已变。ADR 说明在 960×540 下 32 砖是 30 格宽，小人 48–64 高是正常比例。改这个数 = 全部素材重做，要改先写新 ADR。

### Q3 · 原画 → 像素到底怎么「改」　🟡 基本已答

组长定的是「NAI 画原画 → 对着改像素」。[PixelLab入门](../../docs/20-art/PixelLab入门.md) 第 4 节写了具体流程：NAI 原画 → `Image to pixel art` → `Reduce colors` → `Unzoom pixel art` → Aseprite 手修。大致是下面的 C（工具辅助），只是辅助工具用的是 PixelLab 而不是 Retro Diffusion。
仍待确认：是否所有卡面都走这条流程；一致性问题靠先定色板（见 Q4，已定）。

| 选项 | 怎么做 | 取舍 |
|---|---|---|
| A 纯手绘 | 原画只当参考，在 Aseprite 里从零画像素 | 最干净、最慢 |
| B 缩小 + 量化 + 手修 | 原画缩到目标尺寸 → 压色 → 手修 | 快，但要大量清理杂色 |
| C 工具辅助 | 用 Retro Diffusion 的 Pixel Art Fixer 等免费后处理（工作流文档第 4 步）再手修 | 介于两者之间 |

### Q4 · 色板　✅ 已决（2026-11-27，ADR 0004），只剩试压后冻板

**结论：Endesga 64 + 5 个补色 = 69 色**，见 [ADR 0004](../../decisions/0004-主色板Endesga64.md)（组长写，取代已作废的 ADR 0003 AAP-64）。

**组长对四个遗留问题的答复（2026-11-27，经 Alvin 转述；正式规则以 ADR 0004 和之后的 20-art 文档为准）：**

| 问题 | 答复 |
|---|---|
| UI 怎么单独处理 | 不加第二套色板、不额外加色。UI 用 69 色的子集，只是取色规则独立：平涂、高对比、不参与左上光照。语义色锁死：血量 `ea323c`、体力 `5ac54f`、品质 `c7cfdd`（普通）→ `657392`（蓝）→ `93388f`（紫）→ `ffa214`（橙） |
| 专属色上限 | 三层：① 色板补全（全项目共用，不占专属额度）上限 20，已用 5，余 15；② 经营专属 ≤ 8；③ 肉鸽专属每个可玩角色 / 怪物 8 色，≤ 32（4 个角色）。任何缺色先走补全 |
| 明度阶梯不够怎么办 | 随换色板已解决：紫有 9 色约 4 级；黄绿用 4 个补色补到 6 级；深肤色补 `6f462f`。试压后若仍有色系不足，按同样规矩补：成套 3~5 级、从邻近色相延伸、登记进补全清单 |
| 授权要不要联系作者 | 不阻塞进度，署名即可：credits 写 `Palette: Endesga 64 by ENDESGA`。想更稳可发询问留记录，但不要等回复才开工 |

**仍待做：**
- **试压**：用 69 色压 1~3 张真实 NAI 原画（带紫魔法 / 草地植物 / 餐厅暖光各一），通过后才冻板。步骤见 [试压指南](试压指南.md)。
- 5 个补色色值是否合适、深肤色补 1 个够不够：试压后组长定。
- 草地可能偏暗、不够鲜艳（Endesga 纯绿只有 1 个）：试压时留意。
- 授权发布前再核一次（见 ADR 0004 待验证第 3 条）。

**参考（我这边的前期资料，已不是结论）：** [色板重选](色板重选.md)、[色板补色提案](色板补色提案.md)、[色板候选](色板候选.md)、[色板/](色板/README.md)。其中 [色板方案](色板方案.md)、[色板候选](色板候选.md) 讲的是 AAP-64 时期，仅留档。

## 🟡 第二批：开始出某类素材前要定

### Q6 · 角色尺寸　🟡 部分解决

[ADR 0002](../../decisions/0002-基准分辨率与三层尺寸.md) 定了三层：场景小人高 **48–64**，立绘约 **400** 高。**仍待定**：肉鸽战斗角色 / 敌人（平面 2D）的尺寸，Boss 是否更大。

| 场景 | 常见选项 | 备注 |
|---|---|---|
| 经营场景里走动的小人（等距） | ✅ 已定：高 48–64 | 见 ADR 0002 |
| 肉鸽战斗角色 / 敌人（平面 2D） | ⏳ 64 / 96 / 128px 高 | 现在基准分辨率已定，可以据此算 |
| 对话立绘 / CG | ✅ 高约 400 | 像素化方式见 Q7 |

### Q7 · 「CG」到底指什么　🟡 部分解决

画风和尺寸已有结论：立绘走高密度像素二次元（插画降像素，不是 16 色手绘），高约 400，用 NAI → 降像素 → Aseprite 手修（见 [PixelLab入门](../../docs/20-art/PixelLab入门.md) 第 4 节）。
**仍待确认：**

- 战斗里显示的就是这 5 张 CG 吗？还是 CG 是另外的大图（剧情 / 立绘），战斗另有小精灵图？
- 每个状态 **1 张静态图**，还是**多帧动画**？
- 剧情里的厨师长、美少女厨师这些非战斗角色要不要立绘？
- 卡面是竖图还是方图、一张卡在屏幕上多大（PixelLab入门第 11 节也列为待定）

### Q8 · 动画帧数　🟡 部分解决

已定：餐厅里的走动角色**要有动画**，走 PixelLab 的 `Animate`，放在第二阶段，先拿 1 个角色计时再决定给几个角色做。**仍待定**：具体帧数、播放速度，以及肉鸽战斗角色是静态还是动画。

| 动作 | 常见帧数 | 备注 |
|---|---|---|
| 待机 | 静态 / 2~4 帧 | |
| 走路（经营小人） | 4~8 帧 | 已确定要有，帧数待定 |
| 攻击 / 受击 / 死亡 / 放技能 | 静态单张 / 3~6 帧 | 理念 2.9 是按「张」算的，像是静态 |
| 播放速度 | 8 / 10 / 12 帧每秒 | |

> 体量是硬红线（理念第 4 节）。静态 vs 动画，工作量差好几倍。

### Q9 · 等距角色要几个朝向　🟡 倾向已出

组长方向是 **8 方向**（PixelLab `Create 8-directional sprite`），但放第二阶段，**只给必需角色做**，防体量失控。是否最终全用 8 方向，等第二周计时之后再定。

| 选项 | 取舍 |
|---|---|
| 2 方向 + 水平翻转 = 4 方向 | 最省，等距游戏常用 |
| 4 方向（各画一套） | 正背面不对称时用 |
| 8 方向 | 最顺，工作量翻倍（当前倾向，仅限必需角色） |

### Q10 · 描边风格　⏳ 仍待定

| 选项 | 效果 |
|---|---|
| 黑色描边 | 清晰、复古 |
| 彩色描边（跟着物体颜色变深） | 柔和，现代 hi-bit 常见 |
| 无描边 | 更像插画，物体容易糊在背景里 |
| 只对角色描边、场景不描 | 角色从场景里跳出来 |

### Q11 · 图标尺寸　🟡 部分解决

PixelLab入门第 1、6 节写图标量级 **32–64**，练手固定 32–64px。状态小图标是否要 16px 一档仍待定。

| 选项 | 适合 |
|---|---|
| 16px | 状态小图标（格挡、力量……） |
| 24px | 折中 |
| 32px | 物品 / 食材 / 遗物 |
| 48px 以上 | 菜品展示、遗物详情 |

> 可能需要两档：状态图标一档、物品图标一档。

### Q12 · 菜品「按颜色分品质」用哪几色　⏳ 仍待定

理念 2.6 只说按颜色分低 / 中 / 高三级。颜色怎么选、体现在哪（描边？底框？光效？），待定。色板已定，可以从 69 色里挑；ADR 0004 / 组长答复里有一条锁定的 UI 品质色 `c7cfdd → 657392 → 93388f → ffa214`，但那是 UI 语义色，是否同样用于菜品品质，仍要组长 / 策划确认。
