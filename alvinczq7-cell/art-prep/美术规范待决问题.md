# 美术规范待决问题清单（草稿）

> **这里只列选项，不替团队拍板。** 每题给几个常见做法和取舍，最后由组长 / 团队定。
> 定下来的结论要写进 `游戏理念.md` 或 `docs/20-art/`（改「已定参数」要先写 ADR，见 [20-art/README.md](../../docs/20-art/README.md)），不留在这个草稿里。
> 已经定死、**不在讨论范围**的：等距 2:1、左上光照（顶 100% / 左墙 70% / 右墙 50%）、高 hi-bit 像素 + 二次元、经营等距 / 肉鸽平面 2D。

## 🔴 第一批：最先要问组长的（不定下来没法开工）

### Q1 · 游戏内部分辨率（画面「原生」多大）

所有像素尺寸都从这个推出来。按 16:9、能整数放大到 1920×1080 的常见值：

| 选项 | 放大倍数到 1080p | 特点 |
|---|---|---|
| 320×180 | 6 倍 | 很复古，格子大，细节少，画得快 |
| 480×270 | 4 倍 | 折中，很多现代像素游戏用 |
| 640×360 | 3 倍 | 细节多，hi-bit 感强，但每张图工作量大 |

> 引擎还没定（docs/30-tech 是空的），这题最好和写代码的人一起定。

### Q2 · 等距砖块尺寸

[像素等距工作流](../../docs/20-art/像素等距工作流.md) 给的例子是 32，但写的是「32 / 48 / 64」，**没真正定**。PixelLab 等距要求 32~96。

| 选项 | 菱形 | 取舍 |
|---|---|---|
| 32px | 32 宽 × 16 高 | 工作量小，配 320×180 / 480×270 合适；小人只能很小 |
| 48px | 48 × 24 | 中间值 |
| 64px | 64 × 32 | 细节足，配 640×360；建筑、家具工作量翻倍 |

> 一个项目只能有一个砖块尺寸（工作流文档原话），中途改 = 全部重做。

### Q3 · 原画 → 像素到底怎么「改」

组长定的是「NAI 画原画 → 对着改像素」，具体做法有几种：

| 选项 | 怎么做 | 取舍 |
|---|---|---|
| A 纯手绘 | 原画只当参考，在 Aseprite 里从零画像素 | 最干净、最慢 |
| B 缩小 + 量化 + 手修 | 原画缩到目标尺寸 → 压色 → 手修 | 快，但要大量清理杂色 |
| C 工具辅助 | 用 Retro Diffusion 的 Pixel Art Fixer 等免费后处理（工作流文档第 4 步）再手修 | 介于两者之间 |

### Q4 · 色板

| 选项 | 说明 |
|---|---|
| 16 色 | 工作流文档的「标准」；很统一，但 hi-bit 可能不够用 |
| 32 色 | 常见折中 |
| 64 色左右 | 更贴近「高 hi-bit」，统一难度高一点 |
| 来源：Lospec 现成色板 | 直接挑一套，省事 |
| 来源：自定 | 从第一张定稿图里提，更有辨识度 |
| 是否分区 | 经营 / 肉鸽 / UI 用同一套还是各自一套 |

### Q5 · 工具分工和文档对不上，以谁为准（第一行已解决，后两行仍待定）

| 文档写的 | 组长口头定的 | 要问的 |
|---|---|---|
| ~~[AI美术选型](../../docs/20-art/AI美术选型.md)：图标用 Recraft、立绘推 Niji 8~~ | 图标用 **PixelLab**；原画用 **NAI** | ✅ **已解决（2026-11-26）**：组长确认文档写错，以口头方案为准，AI美术选型 已改 |
| 像素等距工作流：后处理用 **Retro Diffusion** | 没提 | RD 的免费后处理要不要纳入流程？ |
| — | PixelLab 暂不充值 | 免费档（工作流文档写的 40 次 + 每天 5 次）能不能先拿来**定规格、做风格锚**？ |

## 🟡 第二批：开始出某类素材前要定

### Q6 · 角色尺寸

| 场景 | 常见选项 | 备注 |
|---|---|---|
| 经营场景里走动的小人（等距） | 约 1~1.5 格高，例如 32px 砖配 24~32px 高的人 | 跟 Q2 绑定 |
| 肉鸽战斗角色 / 敌人（平面 2D） | 64 / 96 / 128px 高 | 跟 Q1 绑定；Boss 可以更大 |
| 对话立绘 / CG | 像素化 or 保留 NAI 原画质感 | 见 Q7 |

### Q7 · 「CG」到底指什么

理念 2.9 写「角色 CG 像素风二次元」，每个角色 5 个状态各 1 张。需要确认：

- 战斗里显示的就是这 5 张 CG 吗？还是 CG 是另外的大图（剧情 / 立绘），战斗另有小精灵图？
- 每个状态 **1 张静态图**，还是**多帧动画**？
- 剧情里的厨师长、美少女厨师这些非战斗角色要不要立绘？

### Q8 · 动画帧数

| 动作 | 常见帧数 | 备注 |
|---|---|---|
| 待机 | 静态 / 2~4 帧 | |
| 走路（经营小人） | 4~8 帧 | |
| 攻击 / 受击 / 死亡 / 放技能 | 静态单张 / 3~6 帧 | 理念 2.9 是按「张」算的，像是静态 |
| 播放速度 | 8 / 10 / 12 帧每秒 | |

> 体量是硬红线（理念第 4 节）。静态 vs 动画，工作量差好几倍。

### Q9 · 等距角色要几个朝向

| 选项 | 取舍 |
|---|---|
| 2 方向 + 水平翻转 = 4 方向 | 最省，等距游戏常用 |
| 4 方向（各画一套） | 正背面不对称时用 |
| 8 方向 | 最顺，工作量翻倍 |

### Q10 · 描边风格

| 选项 | 效果 |
|---|---|
| 黑色描边 | 清晰、复古 |
| 彩色描边（跟着物体颜色变深） | 柔和，现代 hi-bit 常见 |
| 无描边 | 更像插画，物体容易糊在背景里 |
| 只对角色描边、场景不描 | 角色从场景里跳出来 |

### Q11 · 图标尺寸

| 选项 | 适合 |
|---|---|
| 16px | 状态小图标（格挡、力量……） |
| 24px | 折中 |
| 32px | 物品 / 食材 / 遗物 |
| 48px 以上 | 菜品展示、遗物详情 |

> 可能需要两档：状态图标一档、物品图标一档。

### Q12 · 菜品「按颜色分品质」用哪几色

理念 2.6 只说按颜色分低 / 中 / 高三级。颜色怎么选、体现在哪（描边？底框？光效？），待定。
