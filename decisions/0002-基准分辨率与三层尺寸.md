# 0002 · 基准分辨率与三层尺寸

- **日期**：2026-11-26
- **状态**：已采纳
- **决策者**：Mizuki

## 背景

美术要开工，但**所有素材尺寸都没定**，导致三个具体阻塞：

1. **基准分辨率（游戏内部分辨率）没定** → 32px 的砖在屏幕上到底多大、一屏能放几格，都算不出来
2. **tile 尺寸悬着** → [像素等距工作流.md](../docs/20-art/像素等距工作流.md) 写的是「32 / 48 / 64」，没真正拍板
3. **立绘 / 场景 sprite / 砖混在一起谈** → 三层的数和用途不同，混着讨论会得出「32 太小了会糊」这种错结论

另外，`alvinczq7-cell/art-prep/美术规范待决问题.md`（Alvin 的草稿）Q1 只列了 320×180 / 480×270 / 640×360，Q2 的 32px 行写着「配 320×180 / 480×270 合适，小人只能很小」。**本 ADR 的结论与该草稿的选项表不一致**，按 R9 不覆盖他的文件，在此留档说明理由。

## 决定

### 1. 基准分辨率 = 960×540

游戏内部按 **960×540** 画，整张 **×2** 放大到 1080p。所有素材按这张画布的 1:1 像素画，**不按屏幕分辨率画**。

### 2. 等距 tile = 32px（菱形 32×16）

### 3. 三层尺寸分开，互不推导

| 层 | 管什么 | 取值 |
|---|---|---|
| tile | 地砖 | **32** |
| 场景 sprite | 餐厅里走动的小人 | 高 **48–64** |
| 立绘 / 卡面 | 对话、卡牌上的人物 | 高 **约 400** |

## 理由

### 为什么不是 640×360

- **卡牌 UI 放不下**：肉鸽要同时上屏「敌人 + 3 张以上手牌区 + 体力条 + 意图图标」，640 宽挤不下，12px 以下中文基本不可读
- **立绘和 UI 抢地方**：477 宽的立绘在 640 画布上占 75% 屏宽，而卡牌 UI 也要在同一屏上，两者直接冲突；要留白就只能把立绘缩到 ~200 宽，那时候才丢细节。960 画布上立绘占 50%，还剩 480 宽给 UI 和敌人，够用
- 640×360 更适合纯 16-bit 复古风，与本项目「高 hi-bit + 二次元」的美术方向矛盾

### 为什么不选 320 / 480 / 1280×720

| 选项 | 到 1080p | 不选的原因 |
|---|---|---|
| 320×180 | ×6 | 卡牌文字与图标完全放不下；477 宽的立绘比画布还宽（149%），必须先缩到 ≤200 才塞得进 |
| 480×270 | ×4 | 立绘几乎铺满整个屏宽（99%），完全没有 UI 空间 |
| 1280×720 | ×1.5 | **非整数倍，直接糊**。除非目标屏是 1440p（×2），否则排除 |

### 为什么 tile 不用 48 / 64

- **PixelLab 网页 UI 只出 16 / 32**，48 要走 API。项目当前阶段（免费档验证）必须能立刻开工
- 32 是等距 2:1 的标准档，素材生态最多
- 64 让「要画多少」翻 4 倍（面积为 4 倍），与「体量是硬红线」冲突

### 为什么 32 的砖不至于「小人只能很小」

Alvin 草稿里那条判断的前提是「32 砖配 320/480 画布」。在 **960×540** 下，32 砖是 30 格宽，场景 sprite 48–64 高 = 1.5~2 格高，是等距像素游戏的常规比例（星露谷内部 16px 砖配 32px 高角色，同理）。**砖小不等于画面粗**，画面的精细度由色数、描边、阴影层次决定。

## 后果

### 换算基准（验收资产时照这个对）

| 项 | 数值 |
|---|---|
| 1080p 放大倍数 | ×2（整数，不糊） |
| 一屏横放 32px 砖 | 30 格 |
| 竖放行数（等距 32×16） | 约 33 行 |
| 餐厅 14×14 格 | 448×224 px，占屏宽 47% / 屏高 41% |
| 立绘 400 高 | 占屏高 74% |
| 477×653 参考图缩到 400 高 | 宽约 292，占屏宽 30% |

### 约束

- 餐厅建议做 **14×14 格**（10×10 只占屏宽 1/3，偏小）
- **1440p 屏（2560×1440）对 960×540 是 2.67 倍，非整数** → 那类屏需引擎做黑边或 balanced scaling。优先级低，1080p 是主目标
- 改这三个数中任何一个 = 全部素材重做。要改先写新 ADR
- 本决定**不修改** `alvinczq7-cell/` 下任何文件（R9）；Alvin 草稿的 Q1 / Q2 由他本人据本 ADR 更新
