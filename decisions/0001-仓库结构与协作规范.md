# 0001 · 仓库结构与协作规范

- **日期**：2026-11-26
- **状态**：已采纳
- **决策者**：Mizuki

## 背景

游戏开发部需要一块共享地，把企划、设计、美术流程、代码集中起来给组员看。组员各自用不同的 AI（GPT / Claude / Gemini / DeepSeek），如果结构随意，会出现两个可预见的问题：

1. **同一个文档被四家 AI 写出四个版本**，没人知道哪个是准的
2. **同一个概念被翻译成四个英文 key**（`reputation` / `rating` / `fame`），代码一合就炸

## 决定

### 1. 文档权威层级

| 层级 | 文档 | 谁维护 | 冲突时 |
|---|---|---|---|
| 1 | `docs/00-overview/游戏企划书.docx` | Mizuki | **以它为准** |
| 2 | `游戏理念.md`（仓库根目录） | 每日 22:00 自动化 + 人 | 服从企划书 |
| 3 | `docs/**` 专题文档 | 任何人 | 服从上面两层 |

`游戏理念.md` 留在**仓库根目录**、不挪进 `docs/`，理由有两个：每日 22:00 的自动化直接写这个路径，挪走会断归档；放根目录在 GitHub 首页就能点到。

**2026-11-26 修订**：最初写的是「`游戏理念.md` 是唯一事实来源，冲突以它为准」。改为企划书优先——企划书是正式定稿，md 是归档出来的过程文档，地位不该高于它。

### 2. 目录编号

`docs/` 下用数字前缀（`00` / `10` / `20` / `30` / `90`），留出间隔方便以后插入。目录名用**英文小写**，文档名用**中文**。

取舍：中文目录在 URL 里会编码成 `%E6%B8%B8%E6%88%8F`，分享链接容易断；但中文文件名对团队可读性收益很大，所以只对目录名做限制。

### 3. 四份 AI 入口文件，内容不重复

| 文件 | 谁读 | 有没有内容 |
|---|---|---|
| `AGENTS.md` | GPT / Codex / 通用 Agent | **有**，唯一真身 |
| `CLAUDE.md` | Claude Code | 只有指针 |
| `GEMINI.md` | Gemini CLI | 只有指针 |
| `.github/copilot-instructions.md` | GitHub Copilot | 只有指针 |

早期做法是四份各写一份完整规范，结果是改一处漏三处。**现在只有 AGENTS.md 有内容，其余三份只做指向。**

### 4. 术语表是硬约束

`AGENTS.md` 第 6 节的中英对照表，是代码里唯一允许的 key 来源。新增概念必须先加表，再写代码。

### 5. 仓库公开

选择 Public，理由是组员和各家 AI（含网页版）都能直接读，不需要逐个邀请、不需要配 token。代价是内容全网可见。

**补充（2026-11-26，首次推送后发现）**：`游戏理念.md` 末尾的「附：数据源」含本机路径与 QQ 群号，已整段剥离并转存本地 `_local/`（gitignore）。群聊原文按知情同意保留。此后入库前需过一遍：**本机绝对路径、群号、密钥一律不进仓库**。

### 6. 大文件走 LFS

`.psd` / `.aseprite` / 音频 / 字体写进 `.gitattributes`。`.png` 不走 LFS，因为小图标多、走 LFS 反而拖慢 clone。

## 后果

- 好处：任何人（或任何 AI）拿 `AGENTS.md` + `游戏理念.md` 两份文件就能进入状态
- 代价：`INDEX.md` 需要人工维护，忘记登记就会失效 → 已在 `CONTRIBUTING.md` 里列为「新增文档四步」的第三步
- 待观察：四份入口文件会不会有人手贱把内容又抄回去
