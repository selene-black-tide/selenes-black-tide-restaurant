# decisions/ —— 决策记录（ADR）

## 这是什么

记**「为什么当初这么定」**，不记「定成了什么」。定成什么在文档里，理由在这里。

三个月后有人问「为什么不用 Unity」「为什么目录要编号」「为什么仓库是公开的」，答案在这里，不用重新开会。

## 什么时候写

- 改了架构 / 目录结构
- 定了会影响很多文件的技术选型
- **否掉**了一个方案（否定结论比肯定结论更值钱）
- 定了会长期约束项目的美术 / 数值基准

日常小改动不用写。判断标准：**这个决定，三个月后如果有人反对，我需要给他一个理由吗？**

## 怎么写

文件名：`NNNN-一句话标题.md`，四位编号，从 0001 递增。

```yaml
---
title: 0002-一句话标题
status: 定稿        # 草稿 | 定稿 | 废稿，被推翻的写「已作废」并保留原因
updated: 2026-11-26
owner: 谁定的
tags: []
---
```

正文五段：**背景 / 决定 / 后果 / 相关**。决定那段把「选了 A」和「为什么不选 B」都写清楚。
