# 0003 · 色板（已作废）

> **⚠️ 已作废（2026-11-27，定稿后数小时内推翻）**：AAP-64 的**紫色只有 1 个、黄绿只有 1 个**，撑不起本文第 2 条规定「每色系 3~5 级明度」——规则在自己选定的色板上不成立。组长据此要求重选，由 [0004-主色板 Endesga 64 + 补色](0004-主色板Endesga64.md) 取代。
>
> **本文保留的作用**：记录「为什么否掉 AAP-64」与当时的选择依据。正文中的色值、取色表**不再是规范依据**，请以 0004 为准。

- **日期**：2026-11-27
- **状态**：已采纳
- **决策者**：Mizuki

## 背景

色板是卡住第一批正式出图的事，不是细节：

1. [PixelLab入门](../docs/20-art/PixelLab入门.md) 第 4 节的立绘管线是「NAI 出原画 → 降像素 → **`Reduce colors`（压到项目色板）** → Aseprite 手修」，**这一步需要一份现成色板才能执行**
2. 同文档指出这条路「一致性差、色数会炸」——140 张卡面不先定色板，每张会各走各的颜色
3. 等距砖工具（PixelLab）的 `Target palette` 参数要求全项目统一色数
4. 待决问题 Q4（`alvinczq7-cell/art-prep/色板方案.md`、`美术规范待决问题.md`）一直悬着

## 决定

### 2. 明度阶梯规则（和色数同等重要）

**64 色不是 64 个色相，是若干色系 × 3~5 级明度。** 每个色系必须是同一色调由暗到亮的一组，不是并列的一堆不同颜色。

- 每个色系至少 3 级：暗部 / 中间调 / 亮部
- 立绘、怪物等需要立体感的资产用到 4~5 级（含高光、反光）
- 检查方法：把某色系单独排成一列，**应该能看出「从暗到亮」的渐变**；看岀几个并列的深浅相近的色，说明没用上阶梯

### 3. UI 单独处理

- **共用主色板，但不共用取色逻辑**。场景是左上光照（顶 100% / 左墙 70% / 右墙 50%），UI 是平的
- UI 只取主色板里**饱和度 / 明度最高的那几档**，面板底色用蓝灰系 `8b93af / 6d758d / 4a5462 / 333941`
- **独立语义色锁死**：血量 `b4202a`、体力 `14a02e`、品质色按稀有度升序取 `8b93af → 849be4 → bc4a9b → f9a31b`。语义色一旦定下不许改，改了玩家会误读

### 4. 两种时段的标准取色表（已出图验证）

### 5. 角色专属色

AAP-64 的肤色有 6 档（`fef3c0 / fad6b8 / f5a097 / e9b5a3 / f4d29c / dba463`），够做 2~3 套肤色阶梯，但**头发发色不够覆盖 4 个可玩角色 + 多种异族顾客**。

- 允许角色 / 怪物使用**专属色**，上限 **每角色 8 色**
- 专属色规则：① 必须成套（一套 3~5 级明度），不许单色散加 ② 尽量从主色板邻近色相延伸 ③ 登记进色板文件 ④ 优先占用预留的扩展槽
- **不修改主色板已有色值**，只增不改

### 6. 冻板时间点

**测试图通过之后、批量出图之前。**

- 冻结的是三样：**色板文件 + 使用规则 + 明度阶梯**
- 冻后：**新增色系**允许（走上面专属色规则，登记）；**修改已有色值**禁止，要改按本 ADR 的「后果」走新 ADR

## 理由

三套候选都是 Lospec 上标准的 64 色，横向比过：

| 色板 | 平均明度 | 极暗色（L<0.10） | 真肤色档 | 结论 |
|---|---|---|---|---|
| Resurrect 64 | 0.297 | 16 | 2 | ✗ 肤色不够 |
| **AAP-64** | 0.322 | **19** | **6** | ✅ 采用 |
| Endesga 64 | 0.270 | 22 | 2 | ✗ 肤色不够 + 整体太暗 |

**关键判断：**

1. **肤色是硬约束。**「角色 CG 像素风二次元」是核心资产（144 张精修里角色 / 怪物 / 卡面占大头），脸画不立体，前面全白做。Resurrect 和 Endesga 都只有 2 个真肤色，补不回来——补一堆专属色等于主色板失效
2. **「色板平均明度」不等于「画面明度」。** AAP-64 极暗色 19 个，比 Resurrect 还多 3 个。它明度跨度大，正好覆盖「白天餐厅要暖亮 + 午夜地牢要压暗」两种时段（见第 4 节取色表）
3. 排除 Resurrect 64：色值偏灰紫（`2e222f` 那类），地板不像地板、UI 会发紫，且高饱和不足、特效和语义色弱
4. 排除 Endesga 64：UI 的中性灰确实最全（8 级），但整体太暗 + 肤色只有 2 档，二次元角色会发黄

另：本 ADR 是组长看了三套色卡 + 两张同场景模拟图后拍板，不是按印象选的。

## 后果

### 约束

- **改色板 = 全部已出素材重新压色**，和基准分辨率、tile 尺寸同等级；要改先写新 ADR 并评估「已出多少图用了受影响的色」
- 立绘、场景、UI、图标、等距砖**全部**走这一套，不许单开第二套主色板
- 已有色值不许动；扩展只能走专属色口子
- **商用授权**：Lospec 页面未标注明确 license。颜色值本身一般不受版权保护，但稳妥做法是在游戏 credits 里署名作者 **Adigun A. Polack / AAP-64**，正式发布前再核一次

### 待补

- 专属色登记表（按角色建，等第 1 个角色定稿后开始记）
- 菜品「按颜色分品质」的具体色（Q12，属玩法层，色板只保证这些色在池子里有）
