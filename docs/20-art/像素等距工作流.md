# 等距 / 俯视角像素资产 · AI 工作流

> 适用：模拟经营、等距 RPG
> 核心难题：**不是「画不出好看的房子」，是「50 栋房子的光从四面八方来」**

---

## 0. 先分清三种投影（选错全废）

等距项目第一步不是画图，是**确定投影方式**。它决定所有砖块的形状，中途改 = 全部重做。

| 投影 | 格子形状 | 特点 | 代表 |
|---|---|---|---|
| **Isometric（等距）** | 菱形，2:1（宽是高的 2 倍） | 能同时看到顶面 + 两个侧面，立体感最强 | 星际争霸、魔界战记 |
| **Top-down（俯视）** | 正方形 | 正上方看，实现最简单 | 星露谷、宝可梦 |
| **Oblique（斜俯视）** | 正方形顶面 + 侧面向下拉伸 | 顶面是方格但能看见墙，介于两者之间 | 部分模拟经营 |

**PixelLab 的对应参数**：`tile_type` = `isometric` / `square_topdown` / `oblique`
**等距的官方角度表示**：`tile_view_angle = 30`（就代表经典的 2:1 等距）

## 1. 三条"宪法"：开工前必须写死

这三条定歪了，后面每一张图都要返工。

### 宪法一：投影与尺寸

```
投影：isometric 2:1
砖块尺寸：32px（菱形 32 宽 × 16 高）
或 48 / 64px（PixelLab 等距要求 32~96）
```

⚠️ **一个项目只有一个 tile 尺寸。** 不要 32 和 64 混用，缩放会糊。

### 宪法二：光照方向（最容易出问题，最重要）

**写死一个方向，永不改。**

推荐：**光从左上角来（light from upper left）**

这是像素游戏的行业惯例，因为人眼习惯从左上看物体。配套的亮度阶梯：

```
顶面   100% 亮度  ← 最亮
左侧墙  70% 亮度
右侧墙  50% 亮度  ← 最暗
```

⚠️ 不要用「光从正上方」—— 那会导致顶面亮、两侧墙亮暗无法区分，等距的立体感直接消失。

### 宪法三：调色板

**先定色板，再画图。** 不要画完再统一 —— 那是不可能的。

- 标准：**16 色**（像素游戏经典）或 32 色
- 来源：Lospec 上有现成色板库，Retro Diffusion 的 Palette Converter 能直接导入 Lospec
- 所有生成图**必须过同一套量化**

  - **Pixel Art Fixer** —— 把「假的 AI 像素」对齐到真实网格
  - Color Reducer —— 压色数
  - **Palette Converter** —— 全项目统一色板，支持 Lospec
  - Palette Extractor —— 导出 .gpl/.hex/.ase
  - Outline Generator —— 统一描边

### PixelLab —— 等距砖块 + 房间 + 风格锁定

- Free：40 次快速 + 5 次/天
- $12 / $24 / $50 每月（年付省 25%）
- 云端跑，不吃显卡

**等距相关的关键能力（API/MCP 文档已确认）：**

| 参数 / 工具 | 作用 |
|---|---|
| `create_isometric_tile` | 生成单个等距砖块（`"grass on top of dirt"`, `"stone brick wall with moss"`） |
| `tile_view_angle` | 0~90，**等距 30 = 2:1** |
| `elevation` | **0~12，控制建筑高度**（多层楼靠这个） |
| `tile_flat_top_px` | 2（classic）或 4（modern），顶面宽度风格 |
| **`style_copy`** | **从参考图复制 `palette` / `outline` / `shading` / `detail`** ← **这就是锁光照的官方机制** |
| `outline_mode` | `outline`（带描边）或 `segmentation` |
| `layout` | `grid`（更丰富，等距默认）/ `materials`（更一致，且更省额度） |

> `style_copy` 里的 **`shading` 就是把参考图的明暗逻辑复制过来** —— 50 栋建筑的光照统一，靠它。

### Aseprite —— $19.99 买断，必备

手改、拼贴图、切 sprite sheet。AI 给 70 分，最后 30 分靠它。

## 4. 四步工作流

### 第一步：定宪法（半天，不开 AI）

写下三个数字：

```
project.toml
tile_size      = 32
projection     = isometric_2to1
light_source   = upper_left
palette        = 16 colors (Lospec: xxx)
brightness     = top 100% / left wall 70% / right wall 50%
```

**存进项目文档，所有人、所有生成都照这个来。**

### 第二步：做 1 栋"标准建筑"（决定后续 99 栋的成败）

1. 用最高档模型（RD Pro $0.18 或 PixelLab 高档）
2. 一次出 8~16 个候选
3. 挑 1 栋 —— 要求：**顶面/左墙/右墙的亮度对比清晰，光照方向明确是左上**
4. **定为「风格锚」，此后所有生成都以它为参考图**

⚠️ 这一步别省。标准建筑定歪了（比如光看起来像从右上来的），后面全废。

### 第三步：批量生成（锁死参数）

**每一张都必须带同样的三样东西：**

1. 同一张参考图（标准建筑）
2. 固化的 prompt 前缀：
   ```
   isometric, 2:1, 32px tile, light from upper left,
   top surface bright, left wall mid-tone, right wall dark,
   {palette 描述}
   ```
3. 相同的 `style_copy`：`["color_palette", "outline", "shading"]`

**建筑变体的正确做法**（同级建筑出 1/2/3 级）：
- 不要重新生成 → 用**局部重绘 / 垫图**，在标准建筑基础上改
- PixelLab 的 `elevation` 调高度做楼层升级

### 第四步：后处理（必做，不是可选）

```
AI 出图
  → Pixel Art Fixer   （对齐真实像素网格，干掉"假像素"）
  → Color Reducer     （压到调色板色数）
  → Palette Converter （套全项目色板，Lospec 导入）
  → Aseprite 手修     （阴影方向、边缘、细节）
```

**跳过这一步的后果**：图放大到全屏，一眼假 —— 像素边缘会毛、颜色会飘。

## 5. 光照 QC 清单（每 10 张抽检）

等距项目成败就在这一条线。逐张过：

- [ ] 光源方向是左上？（看顶面最亮、右墙最暗）
- [ ] 左墙比右墙亮？
- [ ] 顶面/左墙/右墙的亮度差不小于 25%？
- [ ] 同一建筑的不同等级，光照方向一致？
- [ ] 建筑与地表拼在一起，阴影朝同一方向？
- [ ] 色板色数没超标？
- [ ] 像素对齐真实网格（放大 8 倍看，边缘是硬方块不是糊的）？

**光从四面八方来 = 废图，不管画得多好看。**

## 7. 三个等距特有的坑

1. **一格建筑 ≠ 一格砖。** 一栋房子可能占 2×3 格，而且要用 `elevation` 控制高度。生成时先想清占格数。
2. **墙体两面必须能区分。** 左墙右墙同色 = 变平面。这是等距最基础的立体感来源。
3. **tileset 必须无缝。** 地表用 Wang autotiling（16 张覆盖所有角落组合），不要手拼矩形块。
