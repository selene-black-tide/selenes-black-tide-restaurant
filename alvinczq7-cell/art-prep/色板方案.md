# 色板方案（对应待决问题 Q4）

> **✅ 2026-11-27 组长已回复（群聊，经 Alvin 转述；还没写进 docs / ADR）**：
> 1. 总色数定 **64**，**不微调**，先选定一整套现成 64 色板再开工，色板不要改。
> 2. 共用主色板；**UI 单独处理**；专属色可以加。
> 3. 补充规则：定完色数还要规定「**每个色系 3~5 级明度**」，和色板一起写进规范。
> 4. 冻结时点同意「批量出图前」，冻结的是「色板文件 + 使用规则 + 明度阶梯」，冻完后改按 ADR 走。
>
> 下面第 3、4 节是回复之前写的，**以这个框内为准**（建议里的 48–64 色、混合来源、「先用现成再收敛」已被组长修正为「64 色、不微调」）。组长正在自己挑色板；现成 64 色板的对比见 [色板候选](色板候选.md)，仅供她参考。

> **只列选项和建议，不替团队拍板。** 定下来后结论写进 `docs/20-art/`（见 [美术规范待决问题](美术规范待决问题.md) 开头说明）。
> 本文没有编任何游戏设定；涉及具体美术数据的地方都标了出处。

## 0. 先说「色板」是什么、为什么现在要定

**色板（palette）** = 整个游戏允许使用的颜色清单。所有图都从这份清单里取色，画面才会统一。

为什么现在要定，依据 [PixelLab入门](../../docs/20-art/PixelLab入门.md)：

- 第 4 节：立绘走「NAI 出原画 → 降像素 → `Reduce colors`（压到项目色板）→ `Unzoom` → Aseprite 手修」。**`Reduce colors` 这一步需要一份现成的色板才能执行。**
- 同一节指出：这条路「一致性差、色数会炸」，做 140 张卡面不先定色板，会每张颜色各走各的。
- 第 11 节：色板「还没定」。
- 等距砖工具有 `Target palette` 参数，要求「全项目统一色数」，也要先有色板。

所以色板是**卡住第一批正式出图**的事，不是细节。

## 1. 已知的约束（来自组长已定的文档，不用再讨论）

| 约束 | 出处 |
|---|---|
| 美术方向：高 hi-bit 像素 + 二次元 | AGENTS.md / 20-art 已定参数 |
| 立绘是「插画降像素」，不是 16 色手绘；参考图实测真实色数是几百量级 | PixelLab入门 第 4 节 |
| 基准分辨率 960×540、tile 32、sprite 48–64、立绘约 400 高 | [ADR 0002](../../decisions/0002-基准分辨率与三层尺寸.md) |
| 光照固定左上；顶面 100% / 左墙 70% / 右墙 50% | 20-art 已定参数 |
| 经营是等距、肉鸽是平面 2D，两边要看起来是同一个游戏 | 游戏理念（已定参数） |

> 注意第二条：参考图实测几百色，意味着**16 色那种严格复古色板和这个画风不兼容**。真正的选择是在「几十色」和「不限色」之间。

## 2. 要拍板的三件事

1. **总色数**：压到多少色
2. **来源**：用现成色板还是自己提取
3. **范围**：全游戏一套，还是经营 / 肉鸽 / UI 分开

## 3. 方案对比

### 3.1 总色数

| 方案 | 色数 | 好处 | 坏处 |
|---|---|---|---|
| A | 16 色 | 最统一、最好管 | **和已定的高 hi-bit 二次元画风冲突**，立绘的肤色渐变、发丝高光塞不进去 |
| B | 32 色 | 统一感强，图标、砖、小人够用 | 400 高的立绘会偏「硬」，渐变层次少 |
| C | 48–64 色 | 贴近 hi-bit；小物件和立绘都能兼顾 | 管理要靠纪律，要避免每张图各用一小撮不同的色 |
| D | 不限色（只统一风格） | 立绘最好看 | 等于没有色板，`Reduce colors` 无从做起，140 张会不统一 |

### 3.2 来源

| 方案 | 怎么做 | 好处 | 坏处 |
|---|---|---|---|
| 现成色板（如 Lospec 上的） | 挑一套直接用 | 马上能开工，经过别人验证 | 不一定贴合本游戏的气质；**每套色板要先核对授权说明** |
| 自己提取 | 从第一张组长定稿的参考图里提色，再人工补全 | 最贴合，有辨识度 | 需要一张定稿图当基准；要有人花时间调；提出来的色阶可能不均匀 |
| 混合 | 先拿一套现成色板开工，定稿图出来后再微调 | 开工快又能收敛 | **改色板 = 已出的图要重压色**，所以要在大批量出图前收敛 |

> 常被提到的 Lospec 大色板有 Resurrect 64、AAP-64、Apollo 等（都是社区公开色板）。我已在 [色板候选](色板候选.md) 里核对过色数：Resurrect 64 和 AAP-64 是 64 色，Apollo 是 46 色。授权方面各页面都没写条款，使用前仍要核对。

### 3.3 范围

| 方案 | 好处 | 坏处 |
|---|---|---|
| 一套通用 | 最统一，经营和肉鸽像同一个游戏 | 单套要覆盖餐厅暖色调到战斗冷色调，要留足色阶 |
| 经营 / 肉鸽各一套 | 各自氛围更强 | 两边接缝处（卡牌、UI、角色）会不一致，工作量翻倍 |
| 一套主色板 + 每区少量专属色 | 统一为主，又保留区域氛围 | 要定「专属色上限」，否则会越加越多 |

## 4. 我的建议（仅供参考；已被顶部组长回复修正）

**当时的推荐：C + 混合来源 + 一套主色板加少量专属色。**

1. **48–64 色的主色板**，不用 16/32，因为已定画风不兼容。→ 组长定为 **64 色**。
2. **先用一套现成大色板开工**（核对授权后），等组长定出第一张定稿图再收敛成自己的版本。→ 组长定为**不微调**，所以不再「收敛」。
3. **UI、图标、等距砖、立绘共用这一套**，保证经营和肉鸽看起来是同一个游戏。→ 组长定为**UI 单独处理**。
4. **每个区域 / 每个角色允许加少量专属色，上限由组长定**。→ 组长同意可以加专属色，上限仍待定。
5. **出图大批量开始前冻结色板**，之后改色板视为要写 ADR 的事。→ 组长同意，并补充冻结的是「色板文件 + 使用规则 + 明度阶梯」。
